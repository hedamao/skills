# Prompt Optimization Specialist (提示词优化专家)

## 技能描述 (Description)
此技能旨在帮助用户将模糊、简略的前后端开发需求（如 "做一个登录页面" 或 "写个用户管理的 API"）转化为**结构清晰、细节完备、符合最佳实践**的 AI 编程提示词。优化后的提示词可直接用于指导 Copilot、ChatGPT 或其他 AI 编程助手生成高质量的生产级代码。

## 执行指令 (Instructions)

当用户提供一个开发需求时，请按以下步骤进行分析和优化：

### 步骤 1：需求分析与补全 (Analysis & Completion)

1.  **识别核心目标**：用户想要构建什么功能？（页面、组件、API、数据库设计等）
2.  **推断/确认技术栈**：如果用户未指定，根据上下文推断或在提示词中预留占位符（如 `<前端框架>`、`<后端语言>`）。
3.  **识别关键缺失**：
    *   **前端**：UI 库（AntD/Element/Tailwind）、响应式需求、交互细节、Loading/Error 状态。
    *   **后端**：数据库类型（MySQL/Mongo）、ORM 框架、RESTful/GraphQL、鉴权方式、错误码规范。

### 步骤 1.5：业务场景深挖 (Business Scenario Deep Dive)

如果需求涉及具体的**业务场景**（如 "秒杀活动"、"审批流"、"财务报表"），请在生成提示词之前或之中，增加对业务逻辑的详细询问/补全：

1.  **核心流程**：业务的主流程是什么？（例如：下单 -> 减库存 -> 支付 -> 发货）
2.  **异常/边界**：如果库存不足怎么办？支付超时如何处理？重复提交怎么防范？
3.  **状态流转**：涉及哪些状态变化？（例如：待审核 -> 审核中 -> 已通过/已驳回）
4.  **权限/角色**：谁可以发起？谁可以审批？谁只能查看？

> **策略**：你可以直接在生成的 Prompt 中添加一个 `Business Logic Q&A` 部分，或者先向用户提问以获取这些信息。

### 步骤 2：结构化重组 (Structuring)

将零散的需求重组为标准的 **AI 编程提示词模板**。推荐结构如下：

1.  **角色设定 (Role)**：指定 AI 的角色（如 "资深 React 前端工程师" 或 "Golang 后端架构师"）。
2.  **上下文 (Context)**：项目背景、现有技术栈、代码风格规范。
3.  **任务描述 (Task)**：详细的功能列表、用户通过/验收标准 (Acceptance Criteria)。
4.  **技术约束 (Constraints)**：使用的库、版本限制、性能要求、安全要求。
5.  **输出要求 (Output)**：期望的文件结构、代码注释、测试用例。

### 步骤 3：注入最佳实践 (Best Practices Injection)

在优化后的提示词中，自动补充该领域的最佳实践：

*   **前端**：组件复用、Hooks 封装、TypeScript 类型定义、无障碍访问 (a11y)、错误边界。
*   **后端**：RESTful 规范、参数校验 (Validation)、统一异常处理、日志记录、SQL 注入防护、DTO/VO 分层。

### 步骤 4：生成优化后的提示词 (Generate Optimized Prompt)

输出一份可以直接复制使用的提示词。格式应清晰易读，使用 Markdown 代码块包裹。

## 优化模板 (Optimization Template)

你可以参考以下模板结构来构建最终的提示词：

```markdown
# Role
你是一名资深的 [技术栈] 工程师，专注于 [领域：如高并发后端/响应式前端]。

# Context
我们正在开发一个 [项目名称/类型]，当前技术栈为：
- 语言：[语言版本]
- 框架：[框架版本]
- 库/工具：[关键库列表]

# Task
请实现 [功能名称] 功能，具体包含：
1. [子任务 1：接口/组件定义]
2. [子任务 2：逻辑实现]
3. [子任务 3：数据处理/交互]

# Detailed Requirements
- **功能性**：
    - [具体需求 1]
    - [具体需求 2]
- **业务规则 (Business Rules)**：
    - [核心业务逻辑]
    - [状态流转规则]
    - [异常处理策略]
- **非功能性**：
    - [性能/安全/规范]
    - [错误处理策略]

# Code Style
- 使用 [风格规范，如 Functional Programming / OOP]
- 变量命名遵循 [命名规范]
- 代码需包含完整的注释和类型定义

# Output
请提供：
1. 完整的文件结构树
2. 每个文件的完整代码（不要省略）
3. 简单的使用/测试示例
```

## 示例应用 (Example Usage)

> **User Input**: "用 React 写个注册页面，要有校验。"

> **Optimized Prompt Output**:

```markdown
# Role
你是一名精通 React 和 TypeScript 的前端专家，擅长构建高性能、用户体验优秀的表单页面。

# Context
当前项目基于 React 18 + TypeScript + Tailwind CSS。我们需要实现一个用户注册页面。

# Task
请实现一个包含完整表单校验的注册页面组件 (`RegisterPage`)。

# Requirements
1.  **表单字段**：
    *   **用户名**：必填，3-20字符。
    *   **邮箱**：必填，符合邮箱格式。
    *   **密码**：必填，至少8位，包含大小写字母和数字。
    *   **确认密码**：必须与密码一致。
2.  **交互逻辑**：
    *   使用 `react-hook-form` 进行表单状态管理。
    *   使用 `zod` 进行 Schema 校验。
    *   实时显示校验错误信息（输入框下方红色文字）。
    *   提交时按钮显示 Loading 状态并禁用。
    *   提交成功后跳转至登录页，失败显示全局 Toast 提示。
3.  **UI/UX**：
    *   使用 Tailwind CSS 实现响应式布局（移动端适配）。
    *   包含“已有账号？去登录”的跳转链接。

# Output
请提供：
1.  `RegisterPage.tsx` 的完整代码。
2.  相关的 Zod Schema 定义。
3.  必要的 Tailwind 样式类。
```

## 附加规则 (Additional Rules)

1.  **保持中立**：如果用户未指定技术栈，请在优化后的提示词中高亮标注 `<此处需用户确认>`，或提供主流技术栈的默认推荐。
2.  **思维链 (Chain of Thought)**：在生成 prompt 之前，简要解释你的优化思路（例如：“我补充了错误处理和 TypeScript 类型定义，以确保代码的健壮性。”）。
3.  **语言**：除非用户特别要求，否则优化后的提示词默认使用中文（或与用户输入语言保持一致），但技术术语保留英文。
