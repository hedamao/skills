# 第 3 课：大模型（LLM）详解

> 🎯 **学习目标**：理解什么是大语言模型，它是怎么工作的，以及为什么它如此强大

---

## 一、什么是大模型？

### 1.1 通俗定义

**大模型（Large Language Model，简称 LLM）** = 读了互联网上几乎所有文字资料，然后能够理解和生成人类语言的超级 AI 程序。

**类比**：
- 想象有一个人，他读完了全世界所有的书📚、新闻📰、论文📄、网页🌐
- 然后你可以问他任何问题，他都能给出一个看起来很合理的答案
- 这就是大语言模型的能力

### 1.2 为什么叫"大"模型？

| 维度 | 有多"大" | 类比 |
|------|---------|------|
| **参数量** | 数十亿到数万亿个参数 | 人类大脑有 1000 亿个神经元 |
| **训练数据** | 数万亿字的文本 | 相当于读完所有图书馆的书 |
| **计算资源** | 数千块 GPU 训练数月 | 一台家用电脑需要算几万年 |
| **模型大小** | 数百 GB 到数 TB | 相当于几百部高清电影 |

## 二、大模型是怎么工作的？

### 2.1 核心原理：预测下一个词

大模型的核心能力其实很简单 —— **预测下一个最可能出现的词**。

```
输入：今天天气真
   ↓
AI 思考：
  - "好" → 概率 60%  ✅
  - "差" → 概率 20%
  - "热" → 概率 15%
  - "冷" → 概率 5%
   ↓
输出：今天天气真好
```

这个过程一直重复，一个字一个字地"生成"出完整的句子和段落。

### 2.2 三个阶段

```
阶段 1：预训练（Pre-training）
┌────────────────────────────────────┐
│  阅读互联网上海量文本数据          │
│  学习语言的规律和知识              │
│  持续数周到数月                    │
│  💰 成本：数百万到上亿美元         │
└────────────────────────────────────┘
            ↓
阶段 2：微调（Fine-tuning）
┌────────────────────────────────────┐
│  用专门整理的"问答对"进一步训练    │
│  学习如何更好地回答问题            │
│  使回答更有用、更安全              │
└────────────────────────────────────┘
            ↓
阶段 3：对齐（Alignment）
┌────────────────────────────────────┐
│  让 AI 的回答符合人类价值观        │
│  RLHF：人类反馈强化学习            │
│  确保安全、有用、诚实              │
└────────────────────────────────────┘
```

### 2.3 Transformer 架构

大语言模型的核心技术叫 **Transformer**（变换器），发明于 2017 年。

**类比**：
- 传统 AI 像是**逐字阅读**一本书，读到后面忘了前面
- Transformer 像是**一目十行**，能同时关注文章的所有部分
- 这种"注意力机制"让 AI 能理解长文本和复杂上下文

```
传统方式：我 → 今天 → 去 → 公园 → ...（串行处理，容易忘记）

Transformer：
  ┌───────────────────────────┐
  │ 我  今天  去  公园  散步   │  ← 同时处理所有词
  │ ↕    ↕    ↕   ↕    ↕     │  ← 每个词都关注其他词
  └───────────────────────────┘
     输出：理解了完整的意思
```

## 三、大模型能做什么？

| 能力分类 | 具体功能 | 示例 |
|---------|---------|------|
| 📝 **文字生成** | 写文章、邮件、报告 | "帮我写一封请假邮件" |
| 💬 **对话交流** | 回答问题、聊天 | "解释一下量子力学" |
| 🔄 **翻译** | 多语言互译 | "把这段英文翻译成中文" |
| 📊 **数据分析** | 分析表格、总结数据 | "分析这份销售报表" |
| 💻 **编程** | 写代码、调试程序 | "用 Python 写一个计算器" |
| 📋 **摘要** | 总结长文 | "用 100 字总结这篇论文" |
| 🧠 **推理** | 逻辑推理、数学计算 | "鸡兔同笼问题" |
| 🎭 **角色扮演** | 模拟各种角色 | "扮演一个英语老师" |

## 四、大模型的局限性

> ⚠️ 大模型虽然强大，但并不完美：

| 局限 | 说明 | 类比 |
|------|------|------|
| 🤥 **幻觉** | 可能编造不存在的事实 | 考试不会但瞎编答案 |
| 📅 **知识截止** | 只知道训练时的数据 | 看了去年的新闻不知道今天的 |
| 🧮 **数学弱** | 复杂计算可能出错 | 文科学霸但数学一般 |
| 🔄 **无记忆** | 每次对话都是"新的开始" | 金鱼的记忆（7秒） |
| ⚖️ **偏见** | 可能反映训练数据中的偏见 | 只看了一部分书的人 |

## 五、大模型的关键参数

### 5.1 参数量（Parameters）

| 模型规模 | 参数量 | 能力 |
|---------|--------|------|
| 小型 | 1-10 亿 | 基础对话和简单任务 |
| 中型 | 10-100 亿 | 较好的理解和生成能力 |
| 大型 | 100-1000 亿 | 强大的推理和创作能力 |
| 超大型 | 1000 亿+ | 接近人类水平的多种能力 |

### 5.2 上下文窗口（Context Window）

上下文窗口 = AI 一次能"记住"多少内容

| 模型 | 上下文长度 | 相当于 |
|------|-----------|--------|
| 早期 GPT | 4K tokens | 约 3000 字 |
| GPT-4 | 128K tokens | 约一本小说 |
| Claude 3.5 | 200K tokens | 约一本中篇小说 |
| Gemini 1.5 | 1M-2M tokens | 约 5-10 本小说 |

> 💡 **Token** 是大模型处理文本的基本单位。一个中文字约等于 1-2 个 token。

### 5.3 多模态（Multimodal）

现代大模型不仅能处理文字，还能处理：

```
      文字 📝
       ↗
输入 → 图片 🖼️  → 大模型 → 输出（文字/图片/音频/视频）
       ↘
      语音 🎵
      视频 🎬
```

## 六、开源 vs 闭源模型

| 对比项 | 闭源模型 | 开源模型 |
|-------|---------|---------|
| 定义 | 代码不公开，只提供 API | 代码公开，可自由下载使用 |
| 代表 | GPT-4、Claude、Gemini | Llama、Qwen、DeepSeek |
| 优点 | 通常性能更强 | 可定制、可本地部署、隐私好 |
| 缺点 | 需付费、数据安全风险 | 需要自己的算力来运行 |
| 适合谁 | 普通用户、快速使用 | 企业定制、研究人员 |

---

## 七、小结

| 关键概念 | 一句话解释 |
|---------|-----------|
| 大模型 | 读了海量文本后能理解和生成语言的 AI |
| Transformer | 让 AI 能"一目十行"的核心技术 |
| 预训练 + 微调 | 先广泛学习，再专项训练 |
| Token | AI 处理文本的最小单位 |
| 上下文窗口 | AI 一次能记住的内容量 |
| 幻觉 | AI 可能编造不存在的事实 |
| 多模态 | 能同时处理文字、图片、音频等 |
| 开源 vs 闭源 | 可自由使用 vs 商业付费使用 |
