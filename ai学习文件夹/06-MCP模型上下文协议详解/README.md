# 第 6 课：MCP 模型上下文协议详解

> 🎯 **学习目标**：理解什么是 MCP，为什么它被称为"AI 界的 USB 接口"，以及它如何让 AI 连接外部工具和数据

---

## 一、为什么需要 MCP？

### 1.1 AI 的"孤岛"问题

在没有 MCP 之前，AI 大模型存在一个很大的问题：

```
❌ 没有 MCP 的世界：

  AI 大模型（被困在"孤岛"上）
  ┌──────────────────────┐
  │  我很聪明，但是...     │
  │  ❌ 我无法读你的文件   │
  │  ❌ 我无法查数据库     │
  │  ❌ 我无法上网搜索     │
  │  ❌ 我无法操作其他软件  │
  │  我只能用训练时的知识   │
  └──────────────────────┘
```

每个 AI 产品想要连接外部工具和数据，都需要单独开发接口：

```
❌ 混乱的连接方式：

  ChatGPT ──自定义接口──→ Google 搜索
  ChatGPT ──自定义接口──→ 数据库
  Claude  ──另一种接口──→ Google 搜索  （又要重写！）
  Claude  ──另一种接口──→ 数据库      （又要重写！）
  Gemini  ──再一种接口──→ Google 搜索  （还要重写！）
  
  😱 每个 AI × 每个工具 = 大量重复工作
```

### 1.2 有了 MCP 之后

```
✅ 有 MCP 的世界：

  任何 AI 模型  ←── MCP（统一标准） ──→  任何工具/数据

  ChatGPT ─┐                    ┌─→ Google 搜索
  Claude  ──┼─── MCP 统一协议 ───┼─→ 数据库
  Gemini ──┤                    ├─→ 文件系统
  DeepSeek─┘                    └─→ 任何其他服务

  😎 写一次 MCP 接口，所有 AI 都能用！
```

## 二、什么是 MCP？

### 2.1 正式定义

**MCP（Model Context Protocol，模型上下文协议）** 是一个开放标准协议，它定义了 AI 模型和外部数据源、工具之间的**统一通信方式**。

### 2.2 通俗理解

| 类比 | 说明 |
|------|------|
| 🔌 **USB 接口** | USB 出现前，每个设备用不同的接口。有了 USB，所有设备用同一个接口。MCP 就是 AI 世界的"USB" |
| 🌐 **HTTP 协议** | 网页浏览器用 HTTP 协议访问所有网站。MCP 让 AI 用统一方式访问所有工具 |
| 🔑 **万能钥匙** | 一把钥匙开所有门 —— MCP 让 AI 用一种方式连接所有外部服务 |

### 2.3 MCP 的发明者

MCP 由 **Anthropic**（Claude 的开发公司）在 2024 年底发布，是一个**开源**的标准协议。

## 三、MCP 的架构

### 3.1 三个核心角色

```
┌────────────┐    ┌────────────┐    ┌────────────┐
│  MCP Host  │    │ MCP Client │    │ MCP Server │
│  (宿主应用) │←─→│  (客户端)   │←─→│  (服务端)   │
└────────────┘    └────────────┘    └────────────┘
   Claude           内置在            提供工具
   Cursor           应用中的          和数据的
   等 AI 应用        连接器            服务程序
```

| 角色 | 是什么 | 类比 |
|------|--------|------|
| **MCP Host（宿主）** | 运行 AI 的应用程序 | 你的电脑 |
| **MCP Client（客户端）** | 负责连接的中间件 | USB 线 |
| **MCP Server（服务端）** | 提供具体功能的服务 | U 盘、打印机等设备 |

### 3.2 通信流程

```
用户："帮我查一下项目里有多少个 Python 文件"

  ① 用户 → Host（Claude Desktop）：发出请求
  
  ② Host → Client：需要文件搜索功能
  
  ③ Client → Server（文件系统 MCP Server）：
     "搜索所有 .py 文件"
  
  ④ Server 执行搜索 → 返回结果列表
  
  ⑤ Client → Host：传回搜索结果
  
  ⑥ Host → 用户：
     "项目中共有 42 个 Python 文件，分布如下..."
```

## 四、MCP Server 能提供什么？

MCP Server 可以提供三种类型的能力：

### 4.1 🔧 工具（Tools）

让 AI 能够**执行操作**：

| 工具示例 | 功能 |
|---------|------|
| 文件操作 | 读取、创建、编辑文件 |
| 数据库查询 | 搜索和修改数据 |
| 网页浏览 | 访问网页获取信息 |
| API 调用 | 调用天气、地图等外部接口 |
| 代码执行 | 运行 Python 等代码 |
| 图像生成 | 创建 AI 图片 |

### 4.2 📚 资源（Resources）

让 AI 能够**访问数据**：

| 资源示例 | 说明 |
|---------|------|
| 文件内容 | 读取本地文件 |
| 数据库记录 | 访问数据库中的数据 |
| API 响应 | 获取外部服务的数据 |
| 实时信息 | 股票价格、天气等 |

### 4.3 💡 提示（Prompts）

预定义的**对话模板**，帮助 AI 更好地完成特定任务：

```
例如：一个"代码审查"提示模板

  模板：请审查以下代码，关注：
  1. 代码质量
  2. 潜在 Bug
  3. 性能问题
  4. 安全风险
  
  代码内容：{用户提供的代码}
```

## 五、MCP 实际应用示例

### 5.1 开发场景：在 Cursor/Claude 中使用 MCP

```
场景：用 AI 编程助手开发项目

MCP Servers 配置：
  ├── 📁 文件系统 Server → 读写项目文件
  ├── 🔍 搜索 Server → 搜索代码和文档
  ├── 🗃️ 数据库 Server → 查询和修改数据
  ├── 🌐 浏览器 Server → 查看网页文档
  └── 🖼️ 设计工具 Server → 查看设计稿

这样，AI 就能够：
  ✅ 读懂你的项目代码
  ✅ 搜索 API 文档
  ✅ 直接修改数据库
  ✅ 查看参考网页
  ✅ 对照设计稿开发
```

### 5.2 办公场景：智能办公助手

```
MCP Servers 配置：
  ├── 📧 邮件 Server → 读写邮件
  ├── 📅 日历 Server → 管理日程
  ├── 📄 文档 Server → 编辑 Word/PPT
  ├── 📊 表格 Server → 处理 Excel
  └── 💬 IM Server → 发送消息通知

你说："帮我把昨天的会议纪要整理好，发邮件给团队成员"

AI 通过 MCP：
  ① 从日历 Server 获取昨天的会议信息
  ② 从文档 Server 读取会议记录
  ③ 整理并格式化会议纪要
  ④ 通过邮件 Server 发送给所有参会者
```

## 七、MCP 和其他技术的对比

| 对比项 | MCP | 传统 API | ChatGPT Plugins |
|-------|-----|---------|----------------|
| 标准化 | ✅ 统一标准 | ❌ 各家不同 | ❌ OpenAI 专属 |
| 开放性 | ✅ 开源 | 看具体 API | ❌ 封闭 |
| 通用性 | ✅ 任何 AI 可用 | ✅ 任何程序可用 | ❌ 仅 ChatGPT |
| 安全性 | ✅ 内置权限控制 | 看实现 | ✅ 有审核 |
| 实时性 | ✅ 双向通信 | ✅ 请求/响应 | ⚠️ 有限 |

## 八、如何开始使用 MCP？

### 对于普通用户

1. 使用支持 MCP 的 AI 应用（如 Claude Desktop、Cursor）
2. 在应用设置中添加 MCP Server
3. 开始使用增强后的 AI 能力

### 对于开发者

1. 了解 MCP 协议规范
2. 选择合适的 SDK（Python、TypeScript 等）
3. 开发自己的 MCP Server
4. 发布到社区供他人使用

## 九、小结

| 关键概念 | 一句话解释 |
|---------|-----------|
| MCP | AI 连接外部工具和数据的统一标准协议 |

| Prompts | MCP 中的预定义对话模板 |
